# Valar Production Deployment Guide

This guide details the step-by-step process for deploying the Valar Enterprise Customer Support Copilot app to production. We will host the **Next.js Frontend on Vercel** and the **FastAPI Backend on Railway**, linking them securely using custom environment variables and a persistent disk volume.

---

## SECTION 1: Deploy Frontend to Vercel

Vercel provides native hosting for Next.js applications. Follow these steps to deploy the frontend:

1. **Sign Up / Login**: Go to [vercel.com](https://vercel.com/) and log in using your GitHub account.
2. **Import Project**:
   - Click **Add New** -> **Project**.
   - Import your GitHub repository containing the Valar codebase.
3. **Configure Project Roots**:
   - In the project directory configuration, set the root directory of the Vercel build to `frontend`.
   - Ensure the Framework Preset is set to **Next.js**.
4. **Environment Configuration**:
   - Under the **Environment Variables** tab, add `NEXT_PUBLIC_API_URL` pointing to your deployed Railway backend URL (e.g. `https://valar-backend.up.railway.app`). See Section 5 for details.
5. **Build and Deploy**:
   - Click **Deploy**. Vercel will build the React assets and spin up the Serverless execution endpoints.

---

## SECTION 2: Deploy Backend to Railway

Railway is an excellent platform for deploying Python ASGI applications with persistent storage volumes.

1. **Sign Up / Login**: Go to [railway.app](https://railway.app/) and log in.
2. **Create New Project**:
   - Click **New Project** -> **Deploy from GitHub repo**.
   - Select your Valar repository.
3. **Configure Build Settings**:
   - Set the root directory of the deploy to `Backend` (or set it in your service configurations).
   - Railway will automatically read `Backend/requirements.txt` and `Backend/Procfile` to install Python packages and run the `uvicorn app:app --host 0.0.0.0 --port $PORT` server process.
4. **Disable Ephemeral Rebuilds**:
   - Verify that your Railway project service configuration does not rebuild on arbitrary disk edits, as Chroma database updates generate local I/O.

---

## SECTION 3: Create Railway Persistent Volume

Because SQLite and Chroma operate in-process, their database files must sit on a persistent storage volume to prevent data loss.

1. **Open Railway Dashboard**: Click on your FastAPI backend service block inside the Railway canvas.
2. **Add Volume**:
   - Go to the **Settings** tab.
   - Scroll down to the **Volumes** section and click **Add Volume**.
   - Allocate a minimum of **5GB** or **10GB** depending on the PDF corpus size.
3. **Set Mount Path**:
   - Name the mount path `/app/Backend/persistent_data`.
   - Save the volume. Railway will restart the service container with the persistent directory attached.

---

## SECTION 4: Configure Backend Environment Variables

Configure these keys in the **Variables** tab of your Railway Backend Service:

1. **`OPENROUTER_API_KEY`**: Set your OpenRouter API subscription key. (Required)
2. **`EXA_API_KEY`**: Set your Exa Search fallback API token. (Required)
3. **`SECRET_KEY`**: Provide a strong random secret string (e.g. `79f298c471018804cb9c9e83cd8c9b3a`) to sign user login JWT tokens securely.
4. **`DATABASE_PATH`**: Set this to `persistent_data/users.db`. (Routes SQLite tables into the mounted persistent disk path).
5. **`CHROMA_DB_PATH`**: Set this to `persistent_data/chroma_db`. (Routes Chroma embeddings collections into the persistent disk path).
6. **`UPLOAD_DIRECTORY`**: Set this to `persistent_data/uploaded_files`. (Stores uploaded PDF documents on the persistent disk).
7. **`SETTINGS_PATH`**: Set this to `persistent_data/settings.json`.
8. **`ACTIVITY_LOG_PATH`**: Set this to `persistent_data/activity_logs.json`.
9. **`FRONTEND_URL`**: Set this to your deployed Vercel web domain (e.g. `https://valar-chatbot.vercel.app`) to restrict CORS access safely.
10. **`PORT`**: Railway automatically sets this dynamically. Uvicorn reads this to bind the port.

---

## SECTION 5: Configure Vercel Environment Variables

Set this variable in Vercel to link the client app to the RAG backend:

1. Go to your **Vercel Project Dashboard** -> **Settings** -> **Environment Variables**.
2. Add a new key:
   - **Key**: `NEXT_PUBLIC_API_URL`
   - **Value**: The public URL generated by Railway for your backend (e.g., `https://valar-backend.up.railway.app`). Ensure there is **no trailing slash** at the end.
3. Click **Save** and trigger a redeployment in Vercel to bake the production URL into the Next.js static build.

---

## SECTION 6: Connect Frontend to Backend

1. **Restricted CORS Handshake**:
   - When the backend starts up, it reads `FRONTEND_URL` from its environment. It blocks any arbitrary cross-origin requests except those coming from your Vercel client URL and `localhost:3000` (for testing).
2. **Client Fetching**:
   - Next.js fetches token authentication headers and uploads PDFs directly using the `NEXT_PUBLIC_API_URL` variable.

---

## SECTION 7: Verify Deployment

Once both deployments show a green "Active" status, verify the setup:

1. **Audit Health Endpoint**:
   - Visit the backend root URL (`https://your-backend.up.railway.app/`).
   - You should see the FastAPI greeting message.
2. **Registration and Login**:
   - Go to your Vercel URL.
   - Register a new manager account under `/manager_reg/reg`.
   - Log in successfully to access the chat dashboard.
3. **RAG & Indexing**:
   - Navigate to `/ops_admin` on the Vercel frontend.
   - Upload a test PDF file. Verify that the concurrent queue shows a green "Indexed" badge.
   - Go back to `/` and ask a question relevant to the PDF. Check if Valar cites the document and displays the retrieval score.
4. **Troubleshoot Web Fallback**:
   - Ask a technical question not present in the local database. Verify that Valar falls back to Web Search using Exa API and prints click-through source links.

---

## SECTION 8: Troubleshooting

### Issue 1: Login fails or returns 401 Unauthorized
* **Cause**: Backend cannot decode the token, or the `SECRET_KEY` does not match, or database file is empty/read-only.
* **Solution**: Check the Railway logs. Ensure `DATABASE_PATH` directory is writable. Check that the `SECRET_KEY` is present and consistent.

### Issue 2: Document upload returns "Upload Failed"
* **Cause**: The `uploaded_files` folder or the SQLite/Chroma DB files are not writable, or the disk volume is full.
* **Solution**: Ensure your Railway persistent volume is mounted correctly at `/app/Backend/persistent_data`. Check file permission write logs.

### Issue 3: Next.js console shows "CORS blocked"
* **Cause**: The `FRONTEND_URL` backend variable does not match the Vercel deployment URL or has a trailing slash.
* **Solution**: Edit the backend `FRONTEND_URL` environment parameter to match your exact Vercel URL (e.g., `https://valar-chatbot.vercel.app` without a `/` at the end) and restart the Railway service.
